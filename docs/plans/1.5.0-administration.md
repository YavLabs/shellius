# 1.5.0 — Settings becomes Administration

Status: implemented for 1.5.0 (`feat/administration`). Section table and
redirect mapping: `frontend/src/lib/adminSections.js`; page:
`frontend/src/pages/Administration.jsx`.

## Goal

One **Administration** page for everything an admin configures, with grouped
vertical tabs on the left and the selected section on the right. Users, Roles
and Groups move out of the sidebar into it. Everything shown — the menu entry,
each tab, each action — follows the viewer's permissions, never role names.

## Layout

- **Header:** shield icon, "Administration", subtitle "Configure people,
  security and integrations for this organization."
- **Left column (about 240px, sticky):**
  - a search box that filters tabs by label and keywords (for example
    "smtp" finds Email, "okta" finds Single sign-on);
  - groups with a small heading and a divider between groups;
  - one row per tab: icon and label; the active tab is tinted like the
    sidebar's active item.
- **Right column:** the section in a card, with the section title, a one-line
  description and the section's own actions (for example "Add user").
- **Mobile:** the left column becomes a dropdown picker above the content.
- **Empty search:** "No settings match …" with a Clear button.

## Navigation and permissions

- `ROUTE_ACCESS['/admin']` = the union of every tab's permissions; each tab
  route also checks its own permission (a direct link to a tab you can't see
  redirects to `/admin`, and to the dashboard if you can see no tab).
- The profile menu's "Settings" item becomes **Administration**, shown only
  when the viewer can see at least one tab.
- The sidebar's Administration section (Users, Roles, Groups) is removed.
- Command palette, keyboard shortcuts and help keys point at the new routes.
  Palette entries exist per tab ("Administration › Users", …).
- Old URLs keep working: `/settings` → `/admin`, `/settings?tab=email` →
  `/admin/email` (every old tab key), `/users` → `/admin/users`,
  `/users/:id`, `/roles/:id`, `/groups/:id` likewise. Emails and notifications
  that link to these pages are updated to the new routes too.

## Behaviour details

- Tab state lives in the URL, so back/forward and deep links work.
- Unsaved-changes guard where a tab has a form (keep each tab's existing
  behaviour; don't lose edits on tab switch without asking).
- The Users, Roles and Groups pages keep all current features (tables, bulk
  actions, detail pages, dialogs); only their frame changes. Their page
  headers become the card header inside Administration.
- Permission changes while the page is open (the app re-reads permissions
  on focus) hide or show tabs without a reload.

## Sidebar auto-collapse (done)

Opening the Terminals workspace or Administration collapses the sidebar. It
can still be expanded there with the normal toggle, and that choice holds
while moving between Administration tabs. Leaving restores the saved
preference, which the automatic collapse never changes; the next visit
collapses again. (`AUTO_COLLAPSE_ROUTES` in `components/layout/Sidebar.jsx`.)

## Done when

- Every tab renders inside the new frame in light and dark mode and at
  phone width, with no horizontal scroll.
- A member with none of the permissions sees no Administration entry and is
  redirected from `/admin`.
- A custom role with only `users.view` sees exactly one tab.
- All old URLs redirect correctly.
- Playwright pass over every tab; frontend build and tests pass; docs and
  CHANGELOG updated.
