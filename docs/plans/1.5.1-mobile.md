# 1.5.1 — Mobile redesign

"Mobile" = below Tailwind's `md` breakpoint (768px). Desktop and tablet
(`md` and up) must look and behave exactly as today. Everything follows the
current brand theme (tokens in `frontend/src/index.css`), works in light and
dark mode, respects safe areas (`env(safe-area-inset-bottom)`), and has no
horizontal page scroll at 360–430px widths. Touch targets are at least 44px.

Shared building blocks live in `frontend/src/components/mobile/` and a
`useIsMobile()` hook (`hooks/useIsMobile.js`, matchMedia on `(max-width: 767px)`,
SSR-safe, updates on resize). Prefer CSS (`md:` classes) where a component
can render the same tree for both; use the hook when the tree differs.

## 1. App shell (top bar, bottom navigation, footer)

- **Top bar (mobile):** a single 56px row — menu button, page title,
  search icon, notifications, avatar. The menu button sits inside the bar,
  vertically centred with the other icons (today it floats over the bar,
  misaligned). Quick actions (+), Quick connect (⚡) and the theme toggle
  leave the mobile top bar (theme toggle moves into the menu drawer and the
  account menu).
- **Bottom navigation (mobile only):** fixed, 64px + safe area, blurred
  card background with a hairline top border. Five slots: two nav items,
  a raised centre action button, two nav items. Active item uses the brand
  colour; each item is icon + short label.
  - Nav items are the first four the viewer can open, in this order:
    Dashboard ("Home"), Terminals, Servers, Access requests; fallbacks when
    one isn't allowed: My hosts, Keystore, Sessions, Notifications. Always
    via `canAccessRoute`.
  - Centre button: brand-gradient circle with "+". Tapping opens a bottom
    sheet: **Quick connect** first (when allowed), then the existing quick
    actions (same list and permission rules as the desktop Quick actions
    menu), grouped as today.
  - Hidden on the full-screen terminal page (`/terminal`) and while the
    on-screen keyboard is open in the terminal workspace (the terminal
    needs the height); visible elsewhere.
- **Footer:** hidden on mobile. Page content gets bottom padding so the
  bottom navigation never covers it.
- The menu drawer (full navigation) stays, opened from the top-bar menu
  button.

## 2. Page headers

`components/common/PageHeader.jsx` gets a mobile layout instead of wrapping:

- Row 1: icon + title (single line, truncates), help button at the end.
- Row 2: subtitle (up to two lines, muted).
- Actions: the **primary** action is a full-width button under the
  subtitle (or, when the page opts in, a compact button at the end of the
  title row); every **secondary** action (Refresh, Export, …) moves into a
  "⋯" overflow menu at the end of the title row. Pages mark their primary
  action; if none is marked, the last gradient/primary button is primary.
- Detail pages (for example Customer → Wayne Enterprises) get a back button
  before the title, and their meta line (slug, counts) sits under the title.

## 3. Modals become bottom sheets

On mobile every modal and dialog opens as a sheet from the bottom:

- Rounded top corners (16px), a drag handle, the title row with a close
  button, scrollable body, and a sticky footer for the action buttons
  (full-width, primary last / on the right, stacked when they don't fit).
- Max height 90dvh; body scrolls; the footer stays visible above the
  keyboard (use `dvh`/`visualViewport` where needed); inputs 44px tall,
  `font-size: 16px` so iOS doesn't zoom.
- Swipe down on the handle / header, tap the backdrop or Escape closes
  (same rules as the desktop modal — no closing while a request runs).
- Applies to `components/shared/Modal.jsx`, `components/shared/ConfirmDialog.jsx`
  and `components/ui/dialog.jsx`, so all ~40 modals inherit it. Check the
  big ones (Quick Connect, Add server, SSO provider form, email provider
  form, bulk import) for layout issues inside a sheet.

## 4. Help drawer from the bottom

`components/common/HelpDrawer.jsx` (right-side drawer today) opens as a
bottom sheet on mobile, with the same sheet chrome.

## 5. Data grids become card lists

On mobile no table is shown. `components/shared/DataTable.jsx` renders a
card list instead, following mobile list conventions:

- One card per row: a leading element (avatar / icon / status dot), a
  title line (the row's primary column), a secondary line, then 1–3
  compact meta chips (badges such as environment, status, role), and the
  row's actions: the most important one or two as small buttons, the rest
  in a "⋯" menu (same actions and permissions as the table's row menu).
- Tapping the card does what clicking the row does today.
- Selection (bulk actions): a checkbox on each card and a sticky bulk bar
  above the bottom navigation.
- Toolbar: search full-width; filters collapse into a "Filters" button
  that opens a bottom sheet with the filter controls and a count badge of
  active filters; sort becomes a "Sort" menu.
- Pagination: "Load more" / compact page controls at the end of the list.
- Empty and loading states become card-shaped skeletons.
- Columns opt in with a `mobile` config (which column is the title,
  secondary, meta, leading; which actions are primary). Provide a sensible
  default so every existing table gets a readable card without per-page
  config, then tune each page's table.
- Hand-built tables (Audit log, Customer detail servers, Bulk import
  preview, Roles permission matrix) get their own mobile card/list layout.

## 6. Administration on mobile

- `/admin` on mobile shows the **section list** (grouped, like a phone's
  Settings app: group headings, rows with icon, label, a one-line
  description and a chevron), plus the search box at the top.
- Tapping a section opens it full-width with a back button in the page
  header ("‹ Administration") — no dropdown picker.
- Sections use the card lists (§5), sheets (§3) and page-header rules (§2).
